# 직원카드(10인 에이전트) 실기능 구현 방안

`공급자_납품사이트.html`의 "사이버 가상 본사" 10개 직원 카드를 대상으로, 각 카드가 **지금 실제로 상태를 바꾸는지 / 아직 연출(시뮬레이션)인지**를 정리하고, 프론트엔드 단독(현재 아키텍처: 단일 HTML + localStorage, 서버 없음)으로 바로 개선 가능한 것과, 백엔드·외부 API가 있어야만 진짜가 되는 것을 나눈다.

범례: 🟢 실제 동작(주문 데이터를 실제로 변경) · 🟡 부분 실제(동작은 하지만 로직이 단순/하드코딩) · 🔴 연출만(상태 변화 없음)

---

## 1. 👑 CEO — 제천이 (대표이사)
- **현재**: 🟢 `approveOrderByCeo`, `humanApproveCeo`, `batchApproveByCeo` — 실제로 `ceoApproved`/`status`를 바꾼다. (이번 세션에 `approveOrderByCeo`가 `ceoApproved` 필드를 안 세우던 버그 수정함)
- **가짜인 부분**: "지방계약법 시행령 제25조 적법성 심의"는 텍스트 설명뿐, 금액 한도를 실제로 검증하지 않음 — 2,000만원 초과 건도 그냥 결재 버튼이 눌린다.
- **프론트엔드로 바로 가능한 개선**: 견적 합계금액을 조달몰 계약방법 기준표(100만/500만/2,000만)와 대조해서, 1인 수의계약 한도를 넘는 견적은 결재 버튼을 비활성화하고 "경쟁입찰 필요" 경고를 띄운다. `getHumanReviewStats()`의 `pendingCeo` 필터에 `quoteTotal(q) > 20000000` 체크만 추가하면 됨 — 신규 API 불필요.

## 2. 🗂️ 비서실장 — 슬기
- **현재**: 🟢 `saveDailyBriefing`, `saveNewSchedule`, `deleteSchedule` — `Store.data.schedules`에 실제 CRUD.
- **가짜인 부분**: 일일 결산 브리핑 텍스트를 사람이 직접 타이핑해야 함(자동 집계 아님).
- **프론트엔드로 바로 가능한 개선**: 저장 시점에 `Store.data.orders`에서 오늘 완료/접수 건수·매출 합계를 실제로 집계해 브리핑 초안에 자동으로 채워넣기 (이미 있는 데이터 재사용, 신규 API 불필요).

## 3. 🎧 접수 주임 — 소통이
- **현재**: 🟡 `submitPhoneOrder` — 폼에 입력한 값으로 실제 주문 생성(진짜 데이터 반영).
- **가짜인 부분**: "AI가 통화 메모 분석"이라 되어 있지만 실제로는 사람이 부서/유형/날짜를 수동으로 선택 — `phoneRawText` 원문은 그냥 `note`로 저장될 뿐 파싱되지 않음.
- **프론트엔드로 바로 가능한 개선**: 정규식/키워드 매칭으로 원문에서 "현수막/광고/공사/용역" 키워드, 날짜 표현("이번 주 금요일" 등), 부서명(조직도 목록과 매칭)을 뽑아 자동으로 필드 채우기 — 진짜 LLM 없이도 체감 정확도를 크게 올릴 수 있음.
- **백엔드 필요**: 진짜 자연어 이해(오타·구어체 처리)는 실제 LLM API 연동이 있어야 함 (Phase 2).

## 4. 📊 원가 대리 — 정확이 ✅ 이번 세션에 개선함
- **이전**: 🔴 `banner=450000 / service=300000 / 기타=250000` 3개 값 고정, 수량 무시.
- **현재**: 🟢 `computeAutoQuote(o)`가 `Store.data.catalog`(조달몰 카탈로그, 관리자가 실제로 등록/수정하는 DB)에서 주문 유형에 맞는 상품을 찾아 단가·품목명·규격·단위를 가져오고 `o.detail.qty`(실제 주문 수량)를 곱해 계산. 카탈로그를 수정하면 다음 견적부터 바로 반영됨.
- **다음 개선 여지**: 카탈로그 매칭을 카테고리(cat) 단위가 아니라 상품명 완전 매칭까지 세분화(현재는 카테고리 내 첫 번째 노출 상품을 사용), 다중 품목(현수막 5장 + 설치비 별도 등) 견적 라인 자동 분리.

## 5. 🎨 디자인 선임 — 창의
- **현재**: 🟢 `sendProofToClient`, `approveProofDirectly` — 실제 상태 전이 + 체크리스트 검수.
- **가짜인 부분**: "시안 2종 렌더링"이 실제 이미지가 아니라 텍스트/이모지 카드 — 주문의 실제 문구·규격이 시안에 전혀 반영되지 않음.
- **프론트엔드로 바로 가능한 개선**: `<canvas>` 또는 HTML/CSS만으로 주문의 실제 값(`o.detail.text`, `width`, `height`, `bannerKind`)을 넣은 목업 미리보기를 그려서 "일반적인 예시"가 아니라 "이 주문 전용" 시안처럼 보이게 한다 (진짜 그래픽 디자인은 아니지만 최소한 내용은 실제).
- **백엔드 필요**: 진짜 이미지 생성(AI 시안)은 이미지 생성 API 연동이 필요 (CLAUDE.md Phase 2 로드맵에 이미 명시).

## 6. ⚙️ 공정 주임 — 착착이
- **현재**: 🟢 `startWorkOrder` — 체크박스 확인 후 실제 `status`/`safetyChecked` 갱신.
- **가짜인 부분**: "기상 특보 확인(풍속 10m/s 이하)"이 실제 기상 데이터 없이 체크박스 자율 체크.
- **백엔드 필요**: 기상청 공공API(무료, API 키만 있으면 프론트에서 직접 호출 가능 — 서버 불필요할 수도 있음)로 해당 날짜·지역 강풍특보 여부를 자동 조회해서 체크박스 옆에 실제 특보 상태를 표시. **이건 사실상 프론트엔드 fetch만으로도 가능한 후보** (키 발급만 필요).

## 7. 🚚 물류 주임 — 신속이 ✅ 이번 세션에 개선함
- **이전**: 🔴 "시공 전/후" 카드가 고정 이모지 placeholder, 실제 사진 없음.
- **현재**: 🟢 `uploadSitePhoto`/`removeSitePhoto` — 제출서류 페이지와 동일한 FileReader→base64 패턴으로 실제 이미지를 `o.photoBefore`/`o.photoAfter`에 저장. 둘 다 첨부해야 납품 완료 처리가 통과하도록 검증 추가.
- **다음 개선 여지**: 5MB localStorage 한계상 사진 여러 장/고해상도는 위험 — Phase 2에서 실제 파일 스토리지(Supabase Storage/S3) 연동 시 base64 대신 업로드 URL 저장으로 전환 필요 (CLAUDE.md 15장에 이미 명시된 계획).

## 8. 📑 행정 대리 — 꼼꼼이
- **현재**: 🟡 `b2gDocsPage()` — 실제 주문/견적/설정 데이터를 넣어 `window.print()`로 진짜 인쇄 가능한 문서를 만듦.
- **가짜인 부분**: `b2gDocsPage()`가 orderId 파라미터를 받지 않아서 항상 `orders.filter(...)[0]`(첫 번째 진행중 주문)만 보여준다 — 특정 주문 상세페이지에서 "서류 7종" 버튼을 눌러도 그 주문이 아니라 아무 주문이나 나올 수 있음.
- **프론트엔드로 바로 가능한 개선**: `b2gDocsPage(orderId)`로 파라미터를 받아 `go('b2g-docs', orderId)` 식으로 특정 주문을 넘기도록 수정 (가장 저렴하고 임팩트 큰 다음 작업으로 추천).

## 9. 🧾 세무 주임 — 바른이
- **현재**: 🟢 `approveTaxInvoice`, `humanApproveDocs` — 실제 `taxInvoiced`/`taxInvoiceNo` 세팅.
- **가짜일 수밖에 없는 부분**: 세금계산서 번호가 랜덤 생성이며 실제 국세청 홈택스 API 발행이 아님. **이건 프론트엔드 단독 앱 구조상 원천적으로 진짜가 될 수 없음** — 사업자 인증서·서버 필요.
- **백엔드 필요**: 홈택스 전자세금계산서 발행 API 연동 (Phase 2, CLAUDE.md에 이미 명시).

## 10. 💌 고객케어 — 다정이
- **현재**: 🟢 `sendCareMessage` — 실제 `careSent` 플래그 세팅.
- **가짜인 부분**: "카카오 알림톡 발송"이 실제 카카오 API 호출이 아니라 상태값만 바뀜.
- **백엔드 필요**: 카카오 비즈니스 채널 + 알림톡 템플릿 승인 + 서버 발송 로직 필요 (Phase 2, CLAUDE.md에 이미 명시).

## 우선순위 제안 (프론트엔드만으로 바로 되는 것부터)

| 순위 | 대상 | 작업 | 예상 난이도 |
|---|---|---|---|
| 1 | 꼼꼼이(docs) | `b2gDocsPage(orderId)` 파라미터화 | 낮음 |
| 2 | 제천이(ceo) | 견적 금액이 수의계약 한도 초과 시 결재 차단 | 낮음 |
| 3 | 슬기(secretary) | 일일 브리핑 자동 집계 채우기 | 낮음 |
| 4 | 소통이(intake) | 통화 메모 키워드 기반 자동 필드 채우기 | 중간 |
| 5 | 착착이(work) | 기상청 공공API 강풍특보 자동 조회 | 중간 (API 키 필요) |
| 6 | 창의(design) | 주문 실제 값 반영한 시안 목업(canvas) | 중간 |

## 백엔드가 있어야만 진짜가 되는 것 (Phase 2, CLAUDE.md 15장과 동일)
- 바른이(tax): 홈택스 전자세금계산서 실발행
- 다정이(care): 카카오 알림톡 실발송
- 창의(design): AI 시안 이미지 실생성
- 신속이(deliver): 사진 base64 → 실제 파일 스토리지 전환 (5MB 한계 해소)
